# Requirements Traceability Matrix (RTM)

## AI-Powered Personal Finance & Smart Expenditure Advisor — SRS v1.0

This matrix maps every functional and non-functional requirement from the SRS to the database schema design, identifying tables, columns, constraints, coverage status, and the mandatory application logic required outside the database layer.

| SRS Req ID / Section | Requirement Summary | Related Entities & Tables | Relevant Fields & Constraints | How Schema Supports Requirement | Status | Additional Work Required Outside Database |
| :--- | :--- | :--- | :--- | :--- | :---: | :--- |
| **FR-AUTH-01** | User account creation via approved authentication method. | `users`, `user_profiles` | `users.user_id`, `email`, `password_hash`, `role`, `status`, `uq_users_email` | Stores unique credentials, password hashes, and default profile. | **Covered** | Password validation, Argon2id/Bcrypt hashing service in Express.js. |
| **FR-AUTH-02** | Authenticate returning users before exposing personal financial data. | `users`, `audit_events` | `users.status`, `users.deleted_at`, `audit_events.action` | Tracks user active state and logs authentication events. | **Covered** | JWT token generation, refresh tokens, Express auth middleware. |
| **FR-AUTH-03** | Server-side authorization: user can only access own financial records. | All user-owned tables | `user_id` FK on all tables; composite indices with `user_id` | Enforces referential integrity to `users.user_id`. | **Covered** | Express.js tenant scoping middleware (`WHERE user_id = req.user.id`). |
| **FR-AUTH-04** | Secure session/token expiration and revocation. | `users`, `audit_events` | `users.updated_at`, `audit_events.metadata` | Stores revocation audit traces and password change timestamps. | **Covered** | Redis token blacklisting / session cache; JWT expiry handling. |
| **FR-AUTH-05** | Account deletion/deactivation subject to retention & audit rules. | `users`, `audit_events` | `users.deleted_at`, `users.status = 'DEACTIVATED'` | Supports soft deletion via `deleted_at`; preserves audit trails. | **Covered** | Express endpoint for deactivation; scheduled purge worker for GDPR/DPDP. |
| **FR-AUTH-06** | System shall not request or store bank passwords, PINs, CVVs, OTPs. | Entire schema | Omission of secret fields; `account_mask` limited to 4 digits | Schema contains zero fields for credentials, PINs, or raw OTPs. | **Covered** | Ingestion sanitization filter to strip OTPs before persistence. |
| **FR-CNS-01** | Present user with clear explanation of what data will be processed. | `consents` | `consents.purpose`, `scope`, `consent_version` | Tracks the specific version of explanation shown to user. | **Covered** | Frontend UI consent dialog and terms presentation. |
| **FR-CNS-02** | Record consent status, purpose, timestamp, source, scope. | `consents` | `purpose`, `scope`, `status`, `granted_at`, `ip_address`, `user_agent` | Full auditable consent record per purpose/scope grant. | **Covered** | Client telemetry capture (IP address, user-agent) passed to API. |
| **FR-CNS-03** | Allow user to withdraw consent where technically applicable. | `consents` | `status = 'WITHDRAWN'`, `withdrawn_at` | Marks consent as withdrawn; sets timestamp; retains history. | **Covered** | UI withdrawal button; background job stopping ongoing sync pipelines. |
| **FR-CNS-04** | Prevent new data acquisition after consent expiry or withdrawal. | `consents`, `data_sources` | `consents.status`, `expires_at`, `data_sources.is_active` | Allows checking active consent before processing ingestion jobs. | **Covered** | Express.js middleware checking active consent before queuing ingestion. |
| **FR-CNS-05** | Maintain an auditable consent history. | `consents`, `audit_events` | Append-only consent records, `audit_events` logging | Every grant and revocation creates immutable audit logs. | **Covered** | Regulatory export and audit reporting endpoints. |
| **FR-TXN-01** | Ingest transaction messages only from user-authorized sources. | `data_sources`, `consents` | `data_sources.is_active`, `source_type`, `provider_name` | Explicit configuration of authorized ingestion endpoints. | **Covered** | Android runtime SMS permission checks; user source registration UI. |
| **FR-TXN-02** | Filter candidate financial messages while filtering unrelated texts. | `raw_messages` | `processing_status = 'IGNORED'`, `rejection_reason` | Flags non-financial messages as IGNORED without saving noise. | **Covered** | Android-side keyword pre-filtering and backend NLP classifier. |
| **FR-TXN-03** | Preserve original message only if permitted; store minimized/redacted. | `raw_messages` | `sanitized_preview`, `content_hash` | Stores SHA-256 hash and redacted preview text; no full inbox. | **Covered** | Regex sanitizer replacing card numbers, balances, OTPs with tokens. |
| **FR-TXN-04** | Extract amount, date, type, merchant, reference, account indicator. | `transactions` | `amount`, `transaction_at`, `type`, `merchant_name`, `reference_hash`, `external_reference` | Normalized transactional fields with proper relational keys. | **Covered** | Regex and NLP extraction pipeline in Node.js parser worker. |
| **FR-TXN-05** | Normalize dates, currencies, signs, merchants, and transaction types. | `transactions` | `amount > 0`, `currency = 'INR'`, `type` ENUM, `clean_merchant_name` | Schema enforces canonical values via ENUMs and check constraints. | **Covered** | Normalizer utility standardizing dates to UTC and cleaning merchant strings. |
| **FR-TXN-06** | Mark ambiguous transactions for review rather than inventing values. | `transactions` | `status = 'FLAGGED_FOR_REVIEW'`, `metadata` | Status enum supports flagging ambiguous records for user review. | **Covered** | Parser confidence threshold flagging; UI review queue screen. |
| **FR-TXN-07** | Prevent duplicate ingestion using deterministic & probabilistic deduplication. | `transactions`, `raw_messages` | `uq_raw_messages_hash`, `uq_transactions_account_reference_hash` | Unique indexes on SHA-256 fingerprints prevent duplicate insertions. | **Covered** | Express / BullMQ deduplication query pipeline handling edge cases. |
| **FR-TXN-08** | Support replaying test messages in non-production environments. | `raw_messages`, `import_batches` | `batch_reference`, `parser_version` | Batches and raw messages can be reprocessed without schema changes. | **Covered** | CLI test harness / synthetic message generator script. |
| **FR-TXN-09** | Maintainable provider/bank-specific parsing rules. | `data_sources`, `raw_messages` | `data_sources.metadata`, `raw_messages.parser_version` | References parsing ruleset versions applied to each message. | **Covered** | Pluggable rule engine in Express / Node.js worker modules. |
| **FR-CAT-01** | Prompt user to categorize new transaction when required. | `transactions`, `notifications` | `transactions.is_user_verified = FALSE`, `notification_type = 'SYSTEM'` | Queryable unverified transactions and notification dispatch. | **Covered** | Frontend banner/card prompting user to categorize unverified records. |
| **FR-CAT-02** | Predefined configurable categories (min 14 standard categories). | `categories` | `name`, `category_type`, `user_id IS NULL`, `uq_categories_system_name` | Schema seeds global default categories with user_id NULL. | **Covered** | Seed migration script (`prisma db seed` or SQL script) inserting the 14 categories. |
| **FR-CAT-03** | User selects one category from predefined list for transaction. | `transactions` | `category_id` FK referencing `categories.category_id` | Enforces single-category relational link per transaction. | **Covered** | Category selector dropdown/modal in UI. |
| **FR-CAT-04** | User can create custom category when not available in predefined list. | `categories` | `user_id` populated with user UUID | Supports user-scoped category creation. | **Covered** | "Add Category" modal and API validation in Express. |
| **FR-CAT-05** | Validate custom category names; prevent empty/duplicate definitions. | `categories` | `uq_categories_user_name` unique index on `(user_id, LOWER(name))` | Database index prevents duplicate names per user scope. | **Covered** | Express string trimming, profanity/length validation. |
| **FR-CAT-06** | User-created category associated with creating user for future use. | `categories` | `user_id` FK to `users.user_id` | Queries load system defaults + user custom categories. | **Covered** | API query: `WHERE user_id IS NULL OR user_id = req.user.id`. |
| **FR-CAT-07** | Record selected category, method, confidence, model/rule version. | `categorization_logs` | `method`, `confidence_score`, `model_version` | Audit table captures complete ML/rule decision context. | **Covered** | ML inference worker logging score and version upon assignment. |
| **FR-CAT-08** | User can change or correct the category assigned to a transaction. | `transactions`, `categorization_logs` | `transactions.category_id`, `is_user_verified`, `user_overridden = TRUE` | Updates transaction; appends override entry to categorization log. | **Covered** | API endpoint `PATCH /transactions/:id/category`. |
| **FR-CAT-09** | User corrections retained as feedback for model improvement. | `feedbacks`, `categorization_logs` | `feedbacks.correction_data`, `categorization_logs.user_overridden` | Stores explicit before/after correction feedback for ML retraining. | **Covered** | ML retraining pipeline extracting confirmed pairs from feedbacks. |
| **FR-CAT-10** | Support 'uncategorized' fallback outcome. | `categories`, `transactions` | Global category 'Uncategorized'; `category_id` FK | 'Uncategorized' seeded as default system category. | **Covered** | Default assignment in categorization service when confidence < threshold. |
| **FR-CAT-11** | Recurring-merchant and subscription identification. | `recurring_commitments`, `transactions` | `transactions.is_recurring`, `recurring_commitments` table | Tracks detected subscriptions, expected amount, and cadence. | **Covered** | Background clustering worker detecting periodic transaction intervals. |
| **FR-FIN-01** | Maintain financial profile (income, commitments, budgets, goals). | `user_profiles`, `recurring_commitments`, `budgets`, `financial_goals` | Relational structure connecting all financial planning entities to `user_id` | Directly persists profile, income, and targets in dedicated tables. | **Covered** | Onboarding setup wizard in frontend. |
| **FR-FIN-02** | Calculate total income and expenditure for selected periods. | `transactions` | `amount`, `type` (`DEBIT` vs `CREDIT`), `transaction_at` | Summation queries filter by `transaction_at` and `type`. | **Covered** | Deterministic financial analytics calculation service. |
| **FR-FIN-03** | Calculate category-wise spending. | `transactions`, `categories` | `category_id`, `amount`, `type = 'DEBIT'` | Group by `category_id` aggregated over requested date interval. | **Covered** | Analytics charting query with index support. |
| **FR-FIN-04** | Distinguish debits, credits, refunds, transfers, and fees. | `transactions` | `type` ENUM (`DEBIT`, `CREDIT`, `TRANSFER`, `REFUND`, `REVERSAL`, `FEE`) | Explicit ENUM eliminates ambiguous negative-sign conventions. | **Covered** | Parsing logic mapping bank narrations to correct transaction type. |
| **FR-FIN-05** | Avoid counting internal transfers as consumer expenditure. | `transactions` | `transfer_pair_id`, `type = 'TRANSFER'` | Transfers are paired via self-referencing FK and excluded from expense queries. | **Covered** | Reconciliation algorithm pairing outgoing and incoming legs. |
| **FR-FIN-06** | Expose calculation period and assumptions behind derived metrics. | `advisory_decisions`, `predictions` | `metadata`, `deterministic_factors`, `input_window_start/end` | Persists explicit formulas, date windows, and parameters used. | **Covered** | Explanatory UI tooltip/modal showing arithmetic steps. |
| **FR-BUD-01** | User can create, edit, pause, and delete budgets. | `budgets` | `status` (`ACTIVE`, `PAUSED`, `ARCHIVED`), `created_at`, `updated_at` | Full lifecycle support with status flags and timestamps. | **Covered** | CRUD API routes and UI budget manager. |
| **FR-BUD-02** | Budgets support monthly, weekly, and custom time periods. | `budgets` | `period_type` ENUM, `period_start`, `period_end`, `chk_budgets_period` | Enforces valid start and end dates for any custom period. | **Covered** | Calendar date range picker in UI. |
| **FR-BUD-03** | Budgets optionally assigned to spending categories. | `budgets` | `category_id` NULLABLE, `fk_budgets_categories` | NULL represents total monthly limit; UUID represents category limit. | **Covered** | UI option: "Total Monthly Budget" vs "Category Budget". |
| **FR-BUD-04** | Calculate budget utilization percentage. | `budgets`, `transactions` | `budgets.limit_amount`, `transactions.amount` | Compare sum of category debits against `limit_amount`. | **Covered** | Utilization formula: `(SUM(debits) / limit_amount) * 100`. |

| **FR-BUD-06** | Provide configurable warning thresholds. | `budgets` | `warning_threshold_pct` (`1` to `100`) | User configures custom percentage (e.g. 80%) per budget. | **Covered** | Input slider/field in budget creation modal. |
| **FR-BUD-07** | Use forecast information to warn users of likely future breaches. | `budgets`, `predictions`, `notifications` | `predictions.risk_probability`, `notification_type = 'FORECAST_ALERT'` | Links forecast risk probability to active budget thresholds. | **Covered** | Forecast alerting cron job evaluating active month risk. |

| **FR-ANL-06** | Allow users to filter analytics by date range and category. | `transactions` | `idx_transactions_user_cat_date` composite index | Multi-column B-tree index supports fast filtered range scans. | **Covered** | Filter bar UI and query params in Express. |
